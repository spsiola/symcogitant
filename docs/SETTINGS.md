# Настройки Symcogitant (config.yaml и профили комнат)

В этом документе описаны все конфигурационные параметры агента Symcogitant, где они хранятся и за что отвечают.

## 1. Глобальная конфигурация (`config.yaml`)

Файл `config.yaml` находится в корне проекта и является главным конфигурационным файлом для системы.

### Секция `core`
* **`watchdog_interval`** (int) — интервал в секундах, с которым ядро опрашивает плагины и демоны для подтверждения их работоспособности.

### Секция `daemons` (Фоновые процессы)
Каждый демон имеет секцию `config`:

#### `SystemMonitorDaemon`
* **`interval`** (int) — частота сбора системных метрик и пинга статуса LLM (в секундах).
* **`llm_endpoints`** (dict) — список локальных серверов LLM (Ollama, LM Studio и др.) для проверки их доступности.
* **`openrouter_popular_models`** (list) — список моделей на OpenRouter, для которых периодически загружаются цены и проверяется статус.

#### `FileLoggerDaemon`
* **`ignored_types`** (list) — типы событий в EventBus, которые не нужно писать в файловые логи (например, слишком частые `harness_status`, `metric`).

### Секция `workers` (Обработчики задач)
Воркеры запускаются по событиям из EventBus.

#### `LLMWorker`
* **`base_url`** (string) — URL локального сервера LLM по умолчанию.
* **`api_key`** (string) — API ключ для локального сервера по умолчанию.
* **`default_model`** (string) — модель, которая используется, если не удалось выбрать другую по правилам маршрутизации.
* **`num_ctx`** (int) — размер контекстного окна (в токенах) по умолчанию, передаваемый в LLM.

#### `ModelSelectorWorker`
* **`quarantine_time_sec`** (int) — время в секундах, на которое модель отправляется в карантин, если провайдер возвращает ошибку недоступности (429, 503). (По умолчанию 300).
* **`tiers`** (dict) — списки моделей, разбитые по уровням интеллекта (`smart`, `fast`, `free`). Используются для динамической маршрутизации LLM-запросов (fallback).

### Секция `plugins` (Сенсоры и интерфейсы)

#### `WebInterfacePlugin`
* **`host`** (string) / **`port`** (int) — сетевые настройки для веб-сервера интерфейса.

#### `TelegramTransportPlugin`
* **`session_path`** (string) — путь к папке, где хранится авторизационная сессия пользователя Telegram (Telethon).

#### `LLMChatPlugin`
* **`max_tool_iterations`** (int) — лимит на количество рекурсивных вызовов инструментов (чтобы предотвратить бесконечный цикл `Tool Call -> Response`).

#### `TalksManagerPlugin`
Здесь хранятся глобальные настройки (`talk_defaults`) для всех диалогов (комнат). Эти параметры могут быть переопределены внутри индивидуального `profile.json` для каждой комнаты.

* **`preferred_model_tier`** (string) — какой класс моделей (tier) использовать по умолчанию (например, `smart`).
* **`primary_model`** (string) / **`fallback_model`** (string) — хардкод конкретных моделей для использования (игнорируя tier).
* **`context_window_size`** (int) — количество последних сообщений, удерживаемых в контексте диалога (Sliding Window).
* **`trigger_events`** (list) — на какие события из EventBus должен реагировать менеджер.
* **`trigger_on_mention`** (bool) / **`trigger_on_reply`** (bool) — реагировать ли на прямое упоминание в чате или ответ на сообщение агента.
* **`mention_aliases`** (list) — синонимы имени, на которые откликается агент.
* **`debounce_delay_min`** / **`debounce_delay_max`** (float) — минимальная и максимальная задержка перед ответом (человекоподобная пауза, чтение, печать). Во время этой паузы накапливаются новые сообщения.
* **`background_read_interval_seconds`** (int) — как часто (в секундах) агент самостоятельно "просыпается" в комнате, чтобы обдумать контекст, даже если нет новых сообщений.
* **`background_read_ignore_older_than_days`** (int) — прекращать фоновое чтение, если диалог неактивен дольше указанного количества дней.
* **`append_llm_signature`** (bool) — прикреплять ли системную подпись к ответу агента в чате.
* **`llm_signature_template`** (string) — шаблон подписи, содержащий плейсхолдеры провайдера, потраченных токенов и процента кэширования.
* **`allowed_extra_tools`** (list) — список дополнительных инструментов (Tools), разрешенных в этой комнате.
* **`by_type`** (dict) — переопределение настроек (например, `system_prompt`, `trigger_events`) в зависимости от типа комнаты: `priv` (приватный чат), `group` (группа), `forum` (топик).

## 2. Профили комнат (`data/talks/<protocol>/<room_id>/profile.json`)

Внутри директории `data/talks/` каждая активная беседа изолирована в свою собственную папку. Внутри папки находится файл `profile.json`, который позволяет задать **уникальные настройки для конкретного собеседника или группы**.

Параметры в `profile.json` полностью наследуют и могут переопределять любые ключи из секции `talk_defaults` (описанной выше).

Кроме того, в `profile.json` можно переопределять контекстную схему (`context_schema`), которая диктует `ContextAssemblerWorker` как собирать промпты.

**Пример `profile.json`:**
```json
{
  "system_prompt": "Ты саркастичный программист. Отвечай коротко и с иронией.",
  "preferred_model_tier": "fast",
  "trigger_on_mention": true,
  "debounce_delay_max": 3.0,
  "allowed_extra_tools": ["search_web"]
}
```
Если какой-то параметр отсутствует в `profile.json`, система подтянет его из `config.yaml` -> `talk_defaults`.
