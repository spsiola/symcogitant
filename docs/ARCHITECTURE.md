# Архитектура проекта Symcogitant

Этот документ описывает высокоуровневую архитектуру ИИ-сущности Symcogitant.

ИИ-сущность Symcogitant представляет собой мультимодальную и мультисессионную систему, объединенную через:
- общее состояние запущенного инстанса - весь набор работающих процессов, временных файлов
- общий промпт-идентичности, который инжектится во все контексты при общении с ЛЛМ
- общую память, из которой собираются контексты для "думания" с ЛЛМ каждый раз своим способом, в зависимости от процесса думания
- общие секреты харнесс
- общий харнесс, включающий в себя набор инструментов, набор приборов, набор скилов, набор mcp-сервисов и source code со всей его git историей


symcogitant.py - входная точка в систему, милимальный файл, который разворачивает "жизненный метаболизм":
- запускает циклы "рефлексов" - неЛЛМ watchdogи и прочие контролеров жизнедеятельности
- цикл "сознания" - сессия с ЛЛМ, по временному "тику" и по событиями (обдумать) дергает ЛЛМ, с промптом из текущих события "жизнидеятельности", "лампочек" и "шкал" приборов, состояний прочих "думательных" процессов. Задача - контроль бюджета разных ЛЛМ, частота "тиков" разных "думащих процессов", инициация "думающих" процессов, подтверждение запросов на завершение думающих процессов.
- рефлексивные (неЛЛМ, чисто питоновский скрипт) циклы коммуникации с различными коммуникационными средами: веб-интерфейс, телеграм, дискорд, и др - отслеживание новой инормации типа "мне написали", "обновился чатик, за которым слежу" и запуск отдельных думающих субпроцессов с ЛЛМ типа "коммуникация в канале" - личное общение, общение в группе или чате.

## 2. Основные компоненты (v0.1.7)
- **`symcogitant.py`**: Точка входа, главный цикл (Watchdog), загрузчик конфигурации и плагинов/рефлексов.
- **`config.yaml`**: Централизованная конфигурация системы (список плагинов, рефлексов, порты, API ключи, адреса LLM и интервалы опроса).
- **`EventBus`** (`src/core/event_bus.py`): Очередь событий. Все компоненты общаются только через неё (pub/sub). Сквозь EventBus проходят как высокоуровневые семантические события, так и простые логи для UI.
- **`BasePlugin`** (`src/core/plugin.py`): Абстрактный класс. Содержит логику запуска в виде `asyncio.Task` и функции вроде `emit_log()` и `get_status()`. Плагины и рефлексы наследуются от него.

## Component Communication
- **Event Bus Pattern**: Все компоненты `Symcogitant` (рефлексы и плагины) общаются друг с другом посредством передачи JSON-сообщений через центральный EventBus. Это обеспечивает слабую связность (loose coupling) и асинхронную обработку.
- **Core Plugin Registry (Dependency Injection)**: Для мгновенного доступа к синхронным, статичным или закешированным данным, ядро `SymcogitantCore` прокидывает ссылку на себя во все плагины (`self.core`). Плагины могут использовать метод `core.get_plugin(name)` для получения ссылки на другой плагин и вызова его синхронных методов напрямую. Этот подход используется там, где задержки EventBus (например, при инициализации UI) недопустимы.

## 3. Модули
- **Plugins (`src/plugins`)**: Внешние интерфейсы (Telegram, Web).
  - **`WebInterfacePlugin`**: Поднимает FastAPI/Uvicorn сервер. Раздает статику, предоставляет WebSocket для real-time трансляции событий. Фронтенд работает на базе динамических **Вкладок (Tabs)** для каждого источника событий (каждый плагин имеет свой лог и приборную панель).
  - **`MediaTelegramUserPlugin`**: Асинхронный клиент на базе Telethon. Перехватывает сообщения, реакции и удаленные сообщения от имени пользователя (MTProto) и транслирует их в EventBus. Содержит встроенное кэширование для точной идентификации изменений (добавление/удаление реакций и имена чатов для удаленных сообщений).
- **Reflexes (`src/reflexes`)**: Внутренние "метаболические" циклы и фоновые процессы.
  - **`SystemMonitorReflex`**: Собирает данные о CPU, RAM (`psutil`) и опрашивает статус серверов LLM (`httpx`). Генерирует события типа `metric`.

## Текущие плагины
- **WebInterfacePlugin (`src/plugins/web_interface`)**: Асинхронный веб-сервер на базе FastAPI + Uvicorn, предоставляющий UI для мониторинга. Подписывается на `EventBus` и транслирует все события типа `log` через WebSockets подключенным клиентам в режиме реального времени. Интерфейс реализован с использованием Vanilla JS/CSS (Dark Mode, Glassmorphism). Принимает сырые RAW JSON события и рисует их в консоли отладки.
- **MediaTelegramUserPlugin (`src/plugins/media_telegram_user`)**: Рефлексивный модуль связи с Telegram от имени пользователя. Работает через MTProto (Telethon). Обеспечивает первичное "прослушивание" среды для последующего запуска мысленных LLM-процессов реагирования, а также отправляет ответные сообщения в Telegram.
- **TelegramPrivateDispatcher (`src/plugins/telegram_private_dispatcher`)**: Плагин-маршрутизатор (Router/Dispatcher) для обработки входящих приватных сообщений. Изолирует каждый чат в отдельную `PrivateDialogSession`, автоматически поддерживает Sliding Window и собирает системный промпт (самосознание, когнитивную карту). Буферизует входящие сообщения и отправляет запросы в LLM (через `LLMReflex`).
- **TelegramGroupDispatcher (`src/plugins/telegram_group_dispatcher`)**: Плагин-маршрутизатор для групповых чатов. Запускает `GroupDialogSession`, который сохраняет полную историю сообщений, но отправляет запрос в LLM только при срабатывании триггеров по ключевым словам. Включает логику "человекоподобных" задержек.
