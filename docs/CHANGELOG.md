# История изменений (CHANGELOG)

## [0.1.7] - 2026-09-20
### Добавлено
- Интеграция с провайдером Atria: добавлена поддержка динамического опроса моделей с `https://api.atria-asi.ai/v1/models`.
- Поддержка множества ключей API для одного провайдера. В `data/.env` теперь можно указывать ключи вида `PROVIDER_API_KEY_KeyName`.
- Пользовательский интерфейс: добавлен выпадающий список для выбора ключа API перед отправкой запроса к LLM. Список доступен только если у провайдера более 1 ключа, в остальных случаях он отключен (disabled), чтобы избежать скачков интерфейса.
- Префиксы с количеством ключей (например `[2]`) теперь отображаются в выпадающем списке моделей, чтобы легко отличать провайдеров с множественными ключами.
- Возможность жестко ограничивать контекст для локальных моделей (Ollama) через параметр `num_ctx` (устанавливается из UI).
- Повышена отказоустойчивость: таймаут на опрос провайдеров увеличен с 5 до 10 секунд (решает проблему 503 ошибок).

### Исправлено
- Исправлен баг "пустой вкладки" в WebUI при перезагрузке страницы, вызванный отсутствием вкладки `SystemMonitorReflex` при получении события метрики.
- Устранена ошибка `ReferenceError: globalLlmKeys is not defined`, приводившая к крашу рендеринга виджетов.

## [0.1.6] - 2026-09-20
### Добавлено
- Улучшенный интерфейс для `LLMChatPlugin`: панель заголовка чата с выпадающим списком всех найденных моделей.
- Динамический счетчик символов и подсчет токенов при вводе текста, а также постоянный бэйджик размера текущего контекста (в символах) под селектом модели.
- Добавлена новая расширенная статистика ответа: при получении ответа `LLMReflex` отдает время выполнения (latency), подробный биллинг токенов (prompt, completion, total), а также название ответившей модели и точный таймстемп.
- Вся мета-информация (токенизация, модель, время) сохраняется в `chat_history.json` внутри свойства `metadata` ответов бота.
- Новые инструменты администратора в чате:
  - "Очистить контекст" — кастомное модальное окно с подтверждением очистки. При очистке текущий файл истории архивируется с датой и временем.
  - "Редактировать контекст" — сырое редактирование массива `chat_history.json` с последующей синхронизацией между UI и бэкендом.
  - "Копировать" (копирует сырой массив контекста) и "Копировать все" (копирует текстовый лог чата).
- Прямо в чате (UI) теперь визуально отрисовывается `metadata` (название модели, время генерации, latency) у каждого ответа ассистента.

### Изменено
- Зависимости LLM: переход с устаревшего пакета `google.generativeai` на актуальный `google-genai`.
- `LLMReflex`: добавлена жесткая очистка (фильтрация) всех системных или расширенных полей (вроде `metadata`) перед отправкой сообщений в SDK (Anthropic/OpenAI) для предотвращения крэшей валидации на стороне API-провайдеров.
- WebUI: Использование `min-height: 0` и `flex-shrink: 0` во Flex-контейнерах для устранения бага схлопывания хедеров и меню навигации при большом количестве логов.
- Ядро (Core): улучшена архитектура DI (Dependency Injection), теперь `core` передается всем плагинам для возможности прямого вызова без использования EventBus (полезно для служебных запросов, например, получение текущего статуса `SystemMonitorReflex`).

## [0.1.5] - 2026-09-19
### Добавлено
- Новый плагин `MediaTelegramUserPlugin` (на базе Telethon) для получения сообщений от имени пользователя.
- Скрипт `tools/tg_login.py` для безопасной первичной авторизации Telegram-клиента и сохранения сессии в `data/`.
- Поддержка отслеживания событий создания сообщений, редактирования текстов, установки/снятия эмодзи-реакций и удаления сообщений.
- Внутренний кэш сообщений в Telegram-плагине для точного распознавания удаляемых сообщений и изменений.
- Динамический рендеринг неизвестных системных событий (RAW JSON) на вкладках веб-интерфейса.

### Изменено
- Обновлен веб-интерфейс (`app.js`), добавлена логика игнорирования или RAW-отрисовки семантических событий, предназначенных для LLM.
- Конфигурационный файл `.gitignore` обновлен для защиты директории `data/`, содержащей ключи и сессии.

## [0.1.4] - 2026-09-19
- **Reflexes:** Добавлен `SystemMonitorReflex` (`src/reflexes/system_monitor`) для асинхронного сбора системных метрик (CPU, RAM) с помощью `psutil` и опроса доступности локальных LLM (Ollama, LM Studio, llama.cpp, vLLM, Jan) через `httpx`.
- **UI:** Полный рефакторинг `WebInterfacePlugin`. Реализована система динамических вкладок (Tabs) для каждого источника событий (`source`).
- **UI:** Добавлено отображение метрик (CPU, RAM) и статуса LLM-серверов ("лампочки") в реальном времени.
- **Core:** Изменена фильтрация событий в веб-плагине — теперь на фронтенд пересылаются все типы событий, включая `metric`.

## [0.1.3] - 2026-09-19
- **Core:** Добавлен механизм Watchdog (Heartbeat) в главный цикл ядра для периодического опроса состояния плагинов (интервал задается в `config.yaml` параметром `watchdog_interval`).
- **Core:** Добавлено отслеживание аптайма плагинов (`BasePlugin.get_status()`).
- **Plugins:** Исправлено грязное завершение сервера Uvicorn (`WebInterfacePlugin.stop()`) — теперь Uvicorn закрывается плавно, без выброса `asyncio.CancelledError`.
- **Environment:** Починена конфигурация Pyright в `pyproject.toml` (исправлены пути к виртуальному окружению и заглушен баг `PyYAML`).

## [0.1.2] - 2026-09-19
- **Core:** Реализована базовая точка входа `symcogitant.py` и асинхронный "метаболизм".
- **Core:** Добавлен базовый класс плагина (`BasePlugin`) и шина событий (`EventBus`) для обмена логами.
- **Plugins:** Разработан первый плагин `web_interface` (на базе FastAPI и Uvicorn).
- **UI:** Написан Premium веб-интерфейс для отображения логов работы системы в реальном времени через WebSockets.
- Управление зависимостями и окружением настроено через `uv` (pyproject.toml, uv.lock).
