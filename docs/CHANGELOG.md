# История изменений (CHANGELOG)

## [0.1.12] - 2026-09-22
### Улучшено
- WebUI: Полный рефакторинг интерфейса (вертикальное левое меню с вкладками, контент на всю ширину и высоту экрана).
- WebUI: Добавлена светлая тема с переключателем и сохранением в localStorage.
- WebUI: Добавлена индикация аптайма и версии в левом нижнем углу сайдбара.
- WebUI: Визуальные улучшения (адаптивный скроллбар, исправление цветов JSON в светлой теме).
- WebUI: Улучшение поля "Context Size" — визуальная мигающая подсказка при превышении лимита токенов, валидация ввода (только цифры), отключение браузерных стрелочек увеличения/уменьшения.
- WebUI: Добавлены уникальные идентификаторы `id` и `name` для динамически генерируемых полей во избежание предупреждений браузера.
- Интеграция фавиконок (`favicon`, `apple-touch-icon`) и `site.webmanifest` для PWA.
## [0.1.10] - 2026-09-22
### Улучшено
- Добавлена "человекоподобная" имитация набора текста (статус "печатает...") для `MediaTelegramUserPlugin` во время генерации ответа LLM. Индикатор включается с небольшой случайной задержкой (1-3 секунды) после прочтения входящего сообщения, повышая естественность взаимодействия.
- Сообщения от пользователя мгновенно отмечаются прочитанными (`send_read_acknowledge`) на стороне Telegram в момент начала обработки ответа.

## [0.1.9] - 2026-09-21
### Добавлено
- Реализован плагин `telegram_private_dispatcher` для приватного общения в Telegram.
- Архитектура Router/Dispatcher: Входящие приватные сообщения автоматически маршрутизируются в индивидуальные сессии (`PrivateDialogSession`), изолированные по `chat_id`.
- Управление сессиями:
  - Автоматическое формирование системного промпта из `data/memory/selfhood/` (kernel_identity, cognitive_map, runtime_state).
  - Настраиваемый таймаут неактивности (по умолчанию 1000 секунд), по истечении которого сессия корректно завершается.
  - Поддержка алгоритма "Sliding Window" для удержания контекста (по умолчанию 100 сообщений).
  - Синхронизация запросов к LLM (сообщения от пользователя буферизуются в очереди `incoming_queue` и собираются в один промпт, пока ожидается ответ от LLM).
- `MediaTelegramUserPlugin`: Добавлена поддержка отправки исходящих сообщений через обработчик `telegram_send_message` и фильтрация приватных чатов через флаг `is_private`.
- Исправлен баг, при котором `MediaTelegramUserPlugin` не подписывался на EventBus для получения команд на отправку сообщений.
## [0.1.8] - 2026-09-20
### Добавлено
- `SystemMonitorReflex`: Реализован трехуровневый асинхронный цикл мониторинга (Fast, Medium, Slow).
- `SystemMonitorReflex`: Добавлен автоматический сбор данных о доступных моделях OpenRouter и Atria, а также отслеживание статуса ключей (billing limits). Фильтрация моделей OpenRouter по списку из `config.yaml`.
- Интеграция реестра моделей: все модели, цены, провайдеры и балансы кэшируются в `data/llm_registry.json`. Добавлена логика бекапов реестра.
- `LLMReflex`: Добавлено корректное логирование использования моделей (промпт, генерация, чтение и запись кэша) в файл `data/logs/llm_usage.jsonl`.
- `LLMReflex`: Динамический расчет стоимости запросов `cost_usd` на основе цен, загружаемых напрямую из актуального реестра.
- WebUI: В метриках SystemMonitor теперь отображается статус облачных провайдеров (openrouter, atria), данные берутся из реестра ключей.
- WebUI: Добавлено глобальное модальное окно (Show Registry) для удобного просмотра содержимого `llm_registry.json`.

### Исправлено
- WebUI: Исправлен баг, при котором выпадающий список ключей приводил к `ReferenceError: globalLlmKeys is not defined`.
- WebUI: Улучшен вертикальный скролл на вкладках (теперь блок с метриками фиксирован, а логи прокручиваются отдельно).
- WebUI: Даты и таймстемпы теперь отображаются в удобном относительном формате `timeAgo` (например, "3 min ago").


## [0.1.7] - 2026-09-20
### Добавлено
- Интеграция с провайдером Atria: добавлена поддержка динамического опроса моделей с `https://api.atria-asi.ai/v1/models`.
- Поддержка множества ключей API для одного провайдера. В `data/.env` теперь можно указывать ключи вида `PROVIDER_API_KEY_KeyName`.
- Пользовательский интерфейс: добавлен выпадающий список для выбора ключа API перед отправкой запроса к LLM. Список доступен только если у провайдера более 1 ключа, в остальных случаях он отключен (disabled), чтобы избежать скачков интерфейса.
- Префиксы с количеством ключей (например `[2]`) теперь отображаются в выпадающем списке моделей, чтобы легко отличать провайдеров с множественными ключами.
- Возможность жестко ограничивать контекст для локальных моделей (Ollama) через параметр `num_ctx` (устанавливается из UI).
- Повышена отказоустойчивость: таймаут на опрос провайдеров увеличен с 5 до 10 секунд (решает проблему 503 ошибок).

### Исправлено
- Исправлен баг "пустой вкладки" в WebUI при перезагрузке страницы, вызванный отсутствием вкладки `SystemMonitorReflex` при получении события метрики.
- Устранена ошибка `ReferenceError: globalLlmKeys is not defined`, приводившая к крашу рендеринга виджетов.

## [0.1.6] - 2026-09-20
### Добавлено
- Улучшенный интерфейс для `LLMChatPlugin`: панель заголовка чата с выпадающим списком всех найденных моделей.
- Динамический счетчик символов и подсчет токенов при вводе текста, а также постоянный бэйджик размера текущего контекста (в символах) под селектом модели.
- Добавлена новая расширенная статистика ответа: при получении ответа `LLMReflex` отдает время выполнения (latency), подробный биллинг токенов (prompt, completion, total), а также название ответившей модели и точный таймстемп.
- Вся мета-информация (токенизация, модель, время) сохраняется в `chat_history.json` внутри свойства `metadata` ответов бота.
- Новые инструменты администратора в чате:
  - "Очистить контекст" — кастомное модальное окно с подтверждением очистки. При очистке текущий файл истории архивируется с датой и временем.
  - "Редактировать контекст" — сырое редактирование массива `chat_history.json` с последующей синхронизацией между UI и бэкендом.
  - "Копировать" (копирует сырой массив контекста) и "Копировать все" (копирует текстовый лог чата).
- Прямо в чате (UI) теперь визуально отрисовывается `metadata` (название модели, время генерации, latency) у каждого ответа ассистента.

### Изменено
- Зависимости LLM: переход с устаревшего пакета `google.generativeai` на актуальный `google-genai`.
- `LLMReflex`: добавлена жесткая очистка (фильтрация) всех системных или расширенных полей (вроде `metadata`) перед отправкой сообщений в SDK (Anthropic/OpenAI) для предотвращения крэшей валидации на стороне API-провайдеров.
- WebUI: Использование `min-height: 0` и `flex-shrink: 0` во Flex-контейнерах для устранения бага схлопывания хедеров и меню навигации при большом количестве логов.
- Ядро (Core): улучшена архитектура DI (Dependency Injection), теперь `core` передается всем плагинам для возможности прямого вызова без использования EventBus (полезно для служебных запросов, например, получение текущего статуса `SystemMonitorReflex`).
