# История изменений (CHANGELOG)

## [0.4.1] - 2026-09-22
### Отказоустойчивость и Ошибки (Smart Quarantine)
- В `ModelSelectorWorker` добавлен механизм **Умного Карантина**: при получении ошибок от провайдеров (429 Rate Limit, 503 Service Unavailable) модель отправляется в карантин на заданное время (`quarantine_time_sec`).
- В сессии Телеграм-диспетчеров (`telegram_private_dispatcher`, `telegram_group_dispatcher`) добавлен внутренний **цикл повторных попыток** (`retry loop`). При ошибках LLM сессия не обрывается, а ждет восстановления моделей через событие `models_restored`, после чего автоматически запрашивает fallback-модель.
- Реализовано оповещение пользователя о системных ошибках LLM (попадают в контекст) с автоматическим переключением на запасную модель.

### Улучшения UI и Маршрутизации
- Подпись бота в Telegram теперь формируется динамически: из ответа провайдера извлекается реальная использованная модель (`response_model`) и общие затраты токенов (`total_tokens`). Формат подписи изменен на `<provider>><actual_model> [<tokens> tokens]`.
- В `LLMWorker` добавлена поддержка суффиксов ключей: теперь API ключи можно указывать в `config.yaml` как короткие имена, которые автоматически мапятся на переменные окружения формата `PROVIDER_API_KEY_<suffix>`.

## [0.4.0] - 2026-09-22
### Маршрутизация LLM (LLM Routing)
- В ядро добавлен класс `BaseAgentPlugin` (наследник `BasePlugin`) с поддержкой динамического запроса модели `get_llm_model` и репорта ошибок `report_llm_error`.
- Разработан `ModelSelectorWorker`, отвечающий за выдачу LLM моделей в зависимости от `chat_id` и правил в `config.yaml`.
- Диспетчеры `TelegramPrivateDispatcher` и `TelegramGroupDispatcher` переведены на динамический выбор модели. При отсутствии доступной модели плагин переходит в состояние `paused` (до появления моделей).
- Обновлен UI (`app.js`, `style.css`): для статуса `paused` добавлена желтая индикация в карточках.
### Telegram Плагины и Триггеры
- В `MediaTelegramUserPlugin` добавлено обогащение событий: плагин динамически получает свои `ID` и `username` (через `client.get_me()`) и добавляет флаги `is_reply_to_me` и `mentions_me` ко входящим сообщениям.
- В `TelegramGroupDispatcher` расширена логика активации: теперь бот отвечает не только на ключевые слова, но и на реплаи к своим сообщениям, а также на упоминания своего юзернейма или ссылок вида `t.me/username/`.
- Добавлена логика принудительного игнорирования ответов: если LLM генерирует текст `[NO ANSWER]`, сообщение не сохраняется в контекст истории и не отправляется в Telegram, а статус "печатает..." корректно отменяется.
- Улучшен контроль статуса "печатает": явная отправка события `action: cancel` при таймаутах, ошибках LLM или при решении проигнорировать сообщение.

## [0.3.0] - 2026-09-22
### Security & Tools
- Реализован `SecurityInterceptor` для контроля параметров вызываемых функций. Блокируются команды удаления файлов и попытки выхода за пределы рабочей директории (Directory Traversal).
- Добавлен инструмент `run_command` (`src/tools/os_tools.py`) для выполнения bash/python скриптов на хосте (используется скриптовыми скиллами).
- Внедрена система `Skills` (Навыки) для агентов с поддержкой паттерна Progressive Disclosure. Скиллы в формате Markdown сканируются из `src/skills` и `data/skills` и регистрируются в `ToolsRegistry`.
- Добавлен скилл `skill-creator` (адаптированный от Anthropic) для автономного создания агентами новых скиллов в `data/skills`.
### Core & UI
- Исправлен баг с задержкой отображения статусов во вкладке Harness (теперь `harness_status` отправляется клиенту моментально при WebSocket подключении).
- Исправлено зависание сервера при остановке по `Ctrl+C` (добавлен `os._exit(0)` в процесс завершения для надежного прерывания фоновых потоков `mcp`/`anyio`).
- Интегрирована поддержка Model Context Protocol (MCP) через `MCPManagerDaemon`. Успешно протестировано подключение внешнего сервера погоды `mcp-weather-free` с фиксом SSL сертификатов на macOS.

## [0.2.0] - 2026-09-22
### Архитектура (Ядро)
- Полный рефакторинг архитектуры исполнения: введена новая система базовых классов `BaseModule`, от которого унаследованы `BasePlugin`, `BaseDaemon`, `BaseWorker` и `BaseInterceptor`.
- Загрузчик в `SymcogitantCore` (`symcogitant.py`) переписан для поддержки динамической загрузки из разных папок (например, `src` и `data`) в зависимости от секций конфигурации.
- Конфигурация `config.yaml` разделена на логические блоки: `daemons`, `workers`, `interceptors`, `mcp_servers`, `plugins`.
- Концепт рефлексов удален, вместо него используются фоновые демоны (Daemons) и исполняемые по событиям воркеры (Workers).
- Создан `ToolsRegistry` (`src/core/tools.py`) для управления инструментами. Реализован метод `execute_tool` с поддержкой пайплайна интерцепторов (вызов `pre_tool_call` перед каждым выполнением функции).
### Миграция компонентов
- Системный монитор перенесен из рефлексов в демоны: `src/daemons/system_monitor/daemon.py` (класс `SystemMonitorDaemon`).
- Обработчик LLM перенесен из рефлексов в воркеры: `src/workers/llm_worker/worker.py` (класс `LLMWorker`).
- Обновлены импорты во всех плагинах для соответствия новому ядру `src.core.base`.
- Создан новый `ToolWorker` (`src/workers/tool_worker`), отвечающий за выполнение запрошенных инструментов через `ToolsRegistry`.
- Разработана базовая заглушка `SecurityInterceptor` (`src/interceptors/security_interceptor`) для контроля параметров вызываемых функций.
- В `LLMChatPlugin` реализован механизм оркестрации и рекурсивного вызова инструментов с ограничением `max_tool_iterations`.
### Исправления
- Исправлен потенциальный `TypeError` в ядре при отсутствии инициализированных секций конфигурации (например, пустые `interceptors`).
- В `MediaTelegramUserPlugin` добавлена корректная отмена задач при остановке сервиса.
- В `LLMChatPlugin` исправлен баг рассинхронизации параметров модели при рекурсивном вызове инструментов (теперь `model`, `num_ctx`, `api_key_name` сохраняются и прокидываются повторно).
- В `LLMChatPlugin` добавлена трансляция результатов инструментов обратно в `WebInterfacePlugin` (`ui_chat_output` с ролью `tool`), чтобы контекст в UI (и при копировании) оставался полным.
- В ядре (`symcogitant.py`) реализовано динамическое чтение версии из `pyproject.toml` вместо хардкода в HTML.

### Добавлено
- Интеграция с провайдером Atria: добавлена поддержка динамического опроса моделей с `https://api.atria-asi.ai/v1/models`.

- Возможность жестко ограничивать контекст для локальных моделей (Ollama) через параметр `num_ctx` (устанавливается из UI).
- Повышена отказоустойчивость: таймаут на опрос провайдеров увеличен с 5 до 10 секунд (решает проблему 503 ошибок).

### Исправлено
- Исправлен баг "пустой вкладки" в WebUI при перезагрузке страницы, вызванный отсутствием вкладки `SystemMonitorReflex` при получении события метрики.
- Устранена ошибка `ReferenceError: globalLlmKeys is not defined`, приводившая к крашу рендеринга виджетов.

## [0.1.6] - 2026-09-20
### Добавлено
- Улучшенный интерфейс для `LLMChatPlugin`: панель заголовка чата с выпадающим списком всех найденных моделей.
- Динамический счетчик символов и подсчет токенов при вводе текста, а также постоянный бэйджик размера текущего контекста (в символах) под селектом модели.

- Вся мета-информация (токенизация, модель, время) сохраняется в `chat_history.json` внутри свойства `metadata` ответов бота.
- Новые инструменты администратора в чате:
  - "Очистить контекст" — кастомное модальное окно с подтверждением очистки. При очистке текущий файл истории архивируется с датой и временем.
  - "Редактировать контекст" — сырое редактирование массива `chat_history.json` с последующей синхронизацией между UI и бэкендом.
  - "Копировать" (копирует сырой массив контекста) и "Копировать все" (копирует текстовый лог чата).
- Прямо в чате (UI) теперь визуально отрисовывается `metadata` (название модели, время генерации, latency) у каждого ответа ассистента.

### Изменено
- Зависимости LLM: переход с устаревшего пакета `google.generativeai` на актуальный `google-genai`.
- `LLMReflex`: добавлена жесткая очистка (фильтрация) всех системных или расширенных полей (вроде `metadata`) перед отправкой сообщений в SDK (Anthropic/OpenAI) для предотвращения крэшей валидации на стороне API-провайдеров.
- WebUI: Использование `min-height: 0` и `flex-shrink: 0` во Flex-контейнерах для устранения бага схлопывания хедеров и меню навигации при большом количестве логов.
- Ядро (Core): улучшена архитектура DI (Dependency Injection), теперь `core` передается всем плагинам для возможности прямого вызова без использования EventBus (полезно для служебных запросов, например, получение текущего статуса `SystemMonitorReflex`).
